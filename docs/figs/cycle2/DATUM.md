# The pressure datum, and how much of the shift is real

Generated by `docs/cooper_basin/fault_pressure.py`. Every number below is computed there.


## 1. What is being plotted

The measurement is an **absolute wellhead pressure**. The model computes a **change in fault pore pressure** from `pfinit = 0`. To compare them, the record has to be carried down the well and referenced to the fault's initial pressure:

```
p_fault(t) = p_wh(t) + rho*g*Z - friction(q(t))
dp(t)      = p_fault(t) - p_f0
```
with `Z` = 4100 m the fault's median depth and `friction` the Darcy-Weisbach pipe loss, up to 1.03 MPa at the 60.9 L/s peak and zero when shut in.

**The head does not cancel.** Substituting,

```
dp(t) = p_wh(t) - friction(q(t)) - [p_f0 - rho*g*Z]
                                   ^^^^^^^^^^^^^^^^ the datum
```
so `rho*g*Z` enters **once, additively**. It would only cancel if the datum were itself defined as a wellhead pressure. It is not — it is derived from `p_f0`, which is why `rho` matters directly.

## 3. How much of that is measured, and how much assumed

**Most of it is the column density.** The datum is `p_f0 - rho*g*Z`, so:

| rho kg/m³ | head MPa | datum MPa | move-up |
|---|---|---|---|
| 830 | 33.383 | 39.317 | -4.905 |
| 900 | 36.199 | 36.501 | -2.089 |
| 950 | 38.210 | 34.490 | -0.078 |
| 963 | 38.733 | 33.967 | +0.445 ← implied by the well, see below |
| 1000 | 40.221 | 32.479 | +1.933 ← used |
| 1050 | 42.232 | 30.468 | +3.944 |

That is **2.01 MPa per 50 kg/m³**. The whole "couple of MPa" lies inside the density uncertainty.

**And the well constrains `rho`.** Before any injection the well should be in equilibrium with the virgin reservoir, so `p_wh_static = p_f0 - rho*g*Z`:

```
measured pre-injection wellhead (median, t < 0.501 d) = 33.970 MPa
rho = (72.70 - 33.970)e6 / (9.81 x 4100) = 963 kg/m3
```
With that `rho` the datum **is** the measured static wellhead, 33.970 MPa, and the move-up is only **+0.442 MPa**.

So the accounting is:

| | MPa |
|---|---|
| real — Holl's `p_f0` vs the record's first sample | **+0.44** |
| the rho = 1000 assumption, which the well's own static pressure contradicts | **+1.49** |
| total as plotted | +1.93 |

**The move-up is therefore not a free lever.** It measures how far out of equilibrium the well was at data-day 0. To justify the full 2 MPa one has to argue the column was denser than 963 kg/m³ — cooler or more saline than its own static pressure implies. Three things would settle it, in order of strength: a downhole gauge or temperature log from the completion report; the wellhead elevation, since Holl's depth is mSS and a ~60 m surface elevation adds another 0.59 MPa of column; and whether Habanero 4 was in equilibrium at all in Nov 2012, having been stimulated before.


## 4. An inconsistency this exposes

With the measured stress state — `S_v` = 100 MPa, `S_Hmax` = 160 MPa, dip 10° — the resolved normal stress is

```
sigma_nn = 160 sin^2(10) + 100 cos^2(10) = 101.809 MPa
```
so Holl's `p_f0` = 72.70 implies an effective normal stress of 29.11 MPa. **This project's decks set `sigmainit` = 27.99**, which instead implies `p_f0` = 73.82 — i.e. Taiyi's 73.82 (`setup_model.m:112`), not Holl's.

So `sigmainit` = 27.99 and a datum built on Holl's 72.70 MPa are inconsistent by 1.12 MPa. One or the other should move, and they cannot move independently, since `tau_0 = muinit * sigmainit`. Recorded, not acted on.

An earlier version of this document claimed `p_f0` = 73.82 was confirmed two independent ways, by `sigma_nn - sigmainit` and by the stated `p_pore`. **That was circular** — `sigmainit` was itself derived from that `p_pore`, so the 0.001 MPa agreement proved nothing. Withdrawn.
